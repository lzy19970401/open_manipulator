实机激励与录包：对齐 bringup 的精简流水线

第 6–8 课覆盖了「怎么动」「怎么离线回归」。本课走读当前 open_manipulator_sysid 实机路径：与 open_manipulator_x.launch.py 一样复用 bringup 控制器配置， 只录 /joint_states，离线用 sysid_regress_bag 估摩擦。 重点：launch 顺序、包内还剩哪些文件、τ 从哪读。

相对旧版第 9 课的变化：已删除 hardware_torque_enable、measured_torque、 robot_description.py、sysid 专用 controller yaml。 力矩只走 joint_state_broadcaster 发布的 /joint_states.effort；LSB→N·m 在 bag_to_dataset.py 离线完成。
与 MISSION 的关系：重力补偿假设模型已知；辨识要实测 τ。 实机 position 模式下 effort 常为 Dynamixel Present Current 的原始 LSB， 离线乘以 0.00479627 得到 N·m 再回归。
前置门禁：先跑通 Gazebo（ excitation_gazebo.launch.py → bag → sysid_regress_bag）。实机与 GC launch、 Standard control launch 互斥（同一 USB 口不能同时起两套）。

1. 端到端命令

在线（容器内）：

ros2 launch open_manipulator_sysid excitation_hardware.launch.py port_name:=/dev/ttyUSB0

离线（与 Gazebo 相同）：

ros2 run open_manipulator_sysid sysid_regress_bag \
  --bag open_manipulator_sysid/results/bags/hardware_<时间戳>

可选两步：先 bag_to_dataset --bag ... 得到 .npz， 再 sysid_regress_bag --dataset ...。

在线：bringup 控制器 + excitation_runner → rosbag(/joint_states)
离线：bag → bag_to_dataset（重采样 + effort→N·m）→ regress → results/*.yaml

2. Launch 执行顺序

excitation_hardware.launch.py 与 open_manipulator_x.launch.py 同构：spawner 成功后再动机械臂。

顺序动作为什么
1 ros2_control_node + robot_state_publisher xacro 生成 URDF；加载 bringup 的 hardware_controller_manager.yaml
2 spawner：arm_controller + gripper_controller + joint_state_broadcaster 硬件 on_activate 后 Dynamixel 可跟踪轨迹；开始发 /joint_states
3 excitation_runner + ros2 bag record /joint_states 发傅里叶激励同时录 q、q̇、effort
4 激励结束 → 停 bag → Shutdown 整次 launch 干净退出

excitation_runner（与 Gazebo 相同）：读当前 q → 拼 「慢趋近 q₀ → hold → 傅里叶 → settle」→ /arm_controller/follow_joint_trajectory；订阅 /joint_states 做软限位 / 超速中止。

3. 包内文件分工（当前）

路径角色
launch/excitation_hardware.launch.py 实机 launch；控制器 yaml 来自 open_manipulator_bringup
launch/excitation_gazebo.launch.py 仿真 launch；xacro use_sim:=true，插件内嵌 bringup yaml 路径
config/excitation.yaml sysid 唯一自有配置：q₀、傅里叶、approach/hold、安全上限
excitation_trajectory.py 纯数学：q(t)、安全校验
excitation_runner.py 在线 ROS 节点：发轨迹 + 安全中止
bag_to_dataset.py 读 bag 的 /joint_states；arm_effort_array_to_nm() 换算 τ
identification_dataset.py 均匀重采样、数值 q̈、数据集校验
regress.py → sysid_regress_bag 减 URDF 动力学后最小二乘估 Fv、Fc

4. 为什么复用 bringup，而不是 sysid 专用 yaml？

  1. 实机 launch 显式加载 open_manipulator_bringup/config/open_manipulator_x/hardware_controller_manager.yaml ——与日常 open_manipulator_x.launch.py 相同。
  2. Gazebo 的 xacro 插件参数已写死 bringup 路径；use_sim:=true 即可，无需 robot_description.py 做字符串替换。
  3. joint_state_broadcaster 未指定 joints/interfaces 时，会发布所有 state 接口（含 effort）——实机 effort 如 -102 这类 LSB 会出现在 /joint_states。
  4. ADR-0001 仍成立：不修改 bringup 仓库里的文件；sysid 只引用。

5. 力矩 τ：只录一个话题

阶段来源说明
录包 /joint_states Arm 四关节的 position、velocity、effort
离线 bag_to_dataset.arm_effort_array_to_nm() 若 |effort| > 5 N·m 视为 LSB，× 0.00479627；Gazebo 已是 N·m 则直通
回归 sysid_regress_bag 默认 trim 头 7 s、尾 2.5 s（去掉 approach/hold/settle） 
τ [N·m] ≈ Present_Current_LSB × 0.00479627   （与 GC current xacro 系数一致）

6. 离线默认参数

CLI默认含义
--trim-start7.0 s跳过 approach(5s) + hold(2s)
--trim-end2.5 s跳过 settle hold + 余量
--dt0.01 s均匀重采样周期

输出目录（默认 open_manipulator_sysid/results/）：

  • friction_estimated.yaml
  • inertia_nominal.yaml（URDF 对照，非估计值）
  • report.html
