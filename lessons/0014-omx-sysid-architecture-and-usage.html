open_manipulator_sysid：代码架构、依赖与怎么用

本课回答三个问题：包为什么长成现在这样、跑起来依赖什么、从 GA 到辨识验收按什么顺序敲命令。 代码已按 ADR-0012 拆成域子包；术语与 CONTEXT.md 一一对应。

主参考：仓库 open_manipulator_sysid/README.md、 docs/adr/0011-omx-unified-five-link-bip.md、 docs/adr/0012-omx-sysid-domain-subpackages.md。 先读 第 6 课（傅里叶激励）与 第 13 课（GA）再读本课，负担更小。

1. 架构：用「域」导航，而不是记 20 个文件名

好的架构在这里指：每个子目录对应一个业务概念（seam），改激励就只进 excitation_trajectory/，改录包就只进 excitation_recording/。CLI 名（ros2 run …）保持稳定，实现藏在子包里。

excitation_trajectory/ → 设计 q(t)、GA、Gazebo 发轨迹

excitation_recording/ → bag 读入、对齐、IdentificationDataset

five_link_dynamics/ → 五连杆 SVD 组合 BIP、θ_ref 表

system_identification/ → 联合 LS：θ + Fv/Fc → yaml

model_validation/ → θ 对比、力矩 RMSE、轨迹跟踪图

pinocchio_support/ Pinocchio 加载 URDF/xacro、条件数工具
reference/ 打印 URDF 名义最小参数表
_experimental/ figaroh 等（主路径不 import）

数据流（一条线记全流程）：

excitation.yaml (GA 系数)
    → excitation_runner 跟踪傅里叶段
    → Excitation recording bag（双 topic）
    → bag_reader 重采样 + trim
    → identify 最小二乘
    → dynamics_identified.yaml
    → model_validation 画图 / 对比表

2. 执行依赖：必须先满足什么

层级依赖说明
环境Docker 容器主机勿 colcon build；Pinocchio/ROS 版本与镜像一致
构建colcon build --packages-select open_manipulator_sysid每次改 Python 后 source install/setup.bash
数学Pinocchio + SciPy回归器、RNEA、least_squares
仿真Gazebo + bringup 栈excitation_gazebo.launch.py 拉起控制器与 runner
实机USB Dynamixel + effort 可读excitation_hardware.launch.py；力矩 LSB 在 bag_reader 转 N·m
配置config/excitation.yaml单文件含 ga_coefficients；GA 优化写回同一文件
坑：容器内若 pip install 把 numpy 升到 2.x，apt 的 SciPy 会崩。 见 open_manipulator_sysid/docs/model-validation.md 故障排除段。

3. 子包与关键模块对照

子包关键文件你什么时候碰它
excitation_trajectory/ trajectory.py · ga_optimizer.py · runner.py 改傅里叶/调度；离线 GA；在线发 FollowJointTrajectory
excitation_recording/ bag_reader.py · dataset.py 录包后转均匀采样；辨识前校验数据集有运动
five_link_dynamics/ base_parameters.py · reference_tables.py 理解组合 BIP；打印 θ_ref；五连杆对比 CLI
system_identification/ identify.py · friction.py bag/合成数据联合辨识；输出 dynamics_identified.yaml
model_validation/ evaluation.py · bip_compare.py · torque_plot.py · trajectory_plot.py 短轨迹验收；力矩拟合；指令 vs 测量八张图
pinocchio_support/ model_loader.py 加载 xacro、堆叠回归器（几乎所有离线步骤共用）

辨识口径：五连杆 SVD 组合 BIP + 每关节 Fv/Fc（8 摩擦参数），与 Pinocchio GC 前馈一致。见 ADR-0011。

4. 怎么用：三条常用流水线

流水线 A — 完整系统辨识（Gazebo 或实机）

1 容器内构建并 source（见 §2）。

2（可选）重跑 GA，更新 config/excitation.yaml：

ros2 run open_manipulator_sysid excitation_ga_optimize
ros2 run open_manipulator_sysid sysid_excitation_trajectory_plot   # 看单周期形状

3 仿真录包（默认 5 周期，双 topic）：

ros2 launch open_manipulator_sysid excitation_gazebo.launch.py

4 轨迹验收图（指令来自 controller_state，不是 yaml 重算）：

ros2 run open_manipulator_sysid sysid_trajectory_compare_plot \
  --bag /workspace/sysid_results/bags/gazebo_YYYYMMDD_HHMMSS \
  --output-dir /workspace/sysid_results/trajectory_plots/gazebo_YYYYMMDD_HHMMSS

5 离线辨识：

ros2 run open_manipulator_sysid sysid_identify_bag \
  --bag /workspace/sysid_results/bags/gazebo_YYYYMMDD_HHMMSS \
  --output-dir /workspace/sysid_results

产出：dynamics_identified.yaml（five_link_base_parameters + friction）、report.html。

流水线 B — 模型验证（短轨迹，快）

ros2 launch open_manipulator_sysid test_trajectory_gazebo.launch.py

ros2 run open_manipulator_sysid sysid_bip_urdf_compare \
  --bag /workspace/sysid_results/bags/test_gazebo_… \
  --xacro-mapping use_sim:=true

ros2 run open_manipulator_sysid sysid_torque_compare_plot \
  --bag /workspace/sysid_results/bags/test_gazebo_… \
  --output-dir /workspace/sysid_results/torque_plots

验收主指标：力矩 RMSE，不是逐列惯性「相对误差」（组合 BIP 与单列 URDF 不可直接比）。

流水线 C — 无仿真烟雾测试

pytest src/open_manipulator/open_manipulator_sysid/test -q
ros2 run open_manipulator_sysid sysid_identify_synthetic   # 合成数据辨识

5. 录包与辨识的「接缝」细节

概念来源
Measured joint position/joint_states
Commanded joint position / velocity / acceleration/arm_controller/controller_state 的 reference.*
辨识用 τ/joint_states.effort（Gazebo N·m；实机 LSB→N·m）
辨识时间窗跳过 discard_periods 后的傅里叶段（见 excitation.yaml runtime）

见 ADR-0009。
