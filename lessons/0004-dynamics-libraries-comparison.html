常见动力学库对比：Pinocchio 与朋友们

先分两类：算 τ=g(q)、RNEA 的解析动力学库（控制/规划用）； 与带接触、摩擦、时间积分的物理仿真引擎（验证/ sim 用）。 混为一谈会选错工具。

1. 两类工具

类型 回答的问题 代表
解析动力学 给定 q, q̇, q̈，τ 是多少？g(q)、M(q)、J(q)？ Pinocchio, KDL, RBDL, RBDyn, Drake MultibodyPlant
物理仿真 力/接触作用下，系统随时间怎么演化？ MuJoCo, Gazebo (ODE/Bullet), Isaac Sim
最优控制 在动力学约束下，什么轨迹/力矩最优？ Crocoddyl (+ Pinocchio), Drake TrajectoryOptimization
第 3 课重力补偿属于解析动力学：每周期算 g(q)，不是跑仿真器。 OpenMANIPULATOR 现有实现用 KDL（第 3 课）。

3. 逐个速览

Pinocchio

stack-of-tasks/pinocchio — Featherstone 算法的高效 C++ 实现 + Python。 computeGeneralizedGravity、RNEA、ABA、CRBA、Jacobian， 以及 τ、M 对 q 的解析导数（MPC、Whole-body control 需要）。 论文称相对 RBDL 在多项任务上更快、更灵活 (Carpentier et al., SII 2019)。

KDL（Orocos KDL）

orocos_kinematics_dynamics — ROS 生态里历史最久的链式/树式动力学。 ROBOTIS JntToGravity、你仓库 TreeIdSolver_RNE 都走 KDL。 优势：与 ros2_control / MoveIt 集成成熟、文档/案例多。 劣势：无原生 URDF（靠 kdl_parser）、无解析导数、API 较老。

RBDL

rbdl/rbdl — 同样基于 Featherstone《Rigid Body Dynamics Algorithms》。 RNEA / ABA / CRBA + 基础接触。教学/研究里常见，新项目更常选 Pinocchio。

Drake

drake.mit.edu — 不仅是动力学库，而是建模 + 仿真 + 优化平台。 MultibodyPlant 可算逆动力学；若做轨迹优化、系统级仿真，Drake 合适； 若只需控制器里算 g(q)，引入 Drake 往往过重。

仿真器（对照，不是替代品）

  • MuJoCo — 接触、摩擦、快速 sim；强化学习/抓取 sim 常用；不替代解析 g(q)。
  • Gazebo — OpenMANIPULATOR 已有 launch；ODE/Bullet 积分；适合集成 ROS 2 传感器与可视化。

4. 选型决策（OpenMANIPULATOR 视角）

你的任务推荐理由
重力补偿 g(q)，快速落地 KDL 或 Pinocchio ROBOTIS 已验证 KDL；Pinocchio API 更现代、便于扩展
对比验证 URDF 惯性 Pinocchio + KDL 双算 两库 g(q) 应接近；偏差大 → 查 URDF / 关节轴
Whole-body MPC / OCP Pinocchio + Crocoddyl 需要 ∂τ/∂q 等导数
在 ROS 2 里仿真 OMX Gazebo + ros2_control 已有 launch；与解析库互补
