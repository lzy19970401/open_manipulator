.agents/skills 使用指南

本仓库安装了 Matt Pocock 的 engineering + productivity skills（见根目录 skills-lock.json）。 在 Cursor 对话里输入 /技能名 调用。本文说明何时用、会产出什么。

1. 先用这个：不知道选哪个？

命令何时用产出
/ask-matt 不确定该走哪条工作流 对话中的路径建议（不写入文件）
/setup-matt-pocock-skills 第一次用工程类 skill 之前（一次性） AGENTS.md 的 Agent skills 块；docs/agents/issue-tracker.md、triage-labels.md、domain.md
本仓库已 setup：issue 在 .scratch/（Local markdown），triage 标签为默认五角色，domain 为 single-context。 见 AGENTS.md。

2. 主流程：从想法到实现

有代码库的新功能
/grill-with-docs →（可选 /prototype + /handoff）→ /to-prd → /to-issues → 每 issue 新会话实现

无代码库，只 sharpen 想法
/grill-me（不落盘）

外部进来的 bug/需求
/triage → ready-for-agent 的 issue → 新会话实现

「实现」步骤在 skill 集里没有单独的 /implement——通常在新对话里把 PRD + 单个 issue 交给 Agent 即可。

3. 全部 Skills 一览

用户调用 必须你输入 /name，不占每轮 context
可自动 Agent 或其它 skill 也可唤起
子 skill 通常被别的 skill 内部使用，也可直接 @

命令 类型 什么时候用 使用后会产出什么
配置与路由
/setup-matt-pocock-skills 用户 首次使用 to-prd / triage / to-issues 等之前 AGENTS.md；docs/agents/*.md 三份配置
/ask-matt 用户 迷路时选 flow 文字版路径说明
想法打磨（Grill）
/grill-with-docs 用户 有代码库，要把功能/设计问清楚并写入文档 对话结论；懒创建/更新 CONTEXT.md、docs/adr/*.md（经 domain-modeling）
/grill-me 用户 无代码库或不想落盘，只 interview 仅对话，不写 CONTEXT/ADR
/grilling 可自动 stress-test 任意计划；被 grill-* / triage / improve-* 调用 逐问逐答的设计决策（是否落盘取决于外层 skill）
领域与架构
/domain-modeling 可自动 整理术语、写 glossary、记录 ADR CONTEXT.md；docs/adr/NNNN-*.md（需要时）
/codebase-design 可自动 设计 deep module、定 seam、接口设计 对话中的模块/接口设计；词汇见 skill 内 glossary
/improve-codebase-architecture 用户 有空扫一遍代码库，找「加深模块」机会 系统临时目录下 architecture-review-<timestamp>.html 报告；选中项后进入 grilling
规格 → Issue
/to-prd 用户 当前对话已讨论够多，要合成 PRD（不再 interview） PRD 发布到 issue tracker（本仓库：.scratch/<feature>/PRD.md）；标签 ready-for-agent
/to-issues 用户 把 PRD/计划拆成可独立领取的 vertical slice 多个 issue 文件 .scratch/.../issues/NN-slug.md；带 Blocked by、验收标准
/triage 用户 处理外部进来的 bug/需求/外部 PR；维护者分诊 issue 上 triage 标签/Status；评论（Agent brief / needs-info）；可能 .out-of-scope/*.md
跨会话与原型
/handoff 用户 上下文将满；要新开会话继续 OS 临时目录下的 handoff .md（非 workspace）；含 suggested skills
/prototype 用户 必须用 runnable 代码验证逻辑或 UI 可丢弃的原型代码（终端 app 或多版 UI）；明确标记 throwaway
实现质量
/tdd 可自动 测试先行、red-green-refactor、集成测试 测试代码 + 实现代码（按 skill 的 vertical RED-GREEN 节奏）
/diagnosing-bugs 可自动 难 bug、回归、性能问题；「debug this」 诊断循环产出：复现脚本/测试、根因说明、修复（及可选 learning）
学习与元技能
/teach 用户 在多会话中系统学一个主题（如运动学、Pinocchio） MISSION.md、lessons/*.html、reference/*.html、learning-records/*.md、GLOSSARY.md 等
/writing-great-skills 用户 自己编写/修改 Cursor skill 对话中的 skill 写作建议（参考 skill 内 GLOSSARY）

5. 快速决策

我想…先用
学概念、不上项目/teach
做新功能，还没想清楚/grill-with-docs
讨论够了，要 PRD/to-prd
PRD 要拆 ticket/to-issues
处理 GitHub/本地 issue 队列/triage
代码库结构变乱/improve-codebase-architecture
bug 查不出原因/diagnosing-bugs
整理 OMX 领域词/domain-modeling
对话太长要换会话/handoff

6. 上下文卫生（重要）

  • grill → to-prd → to-issues 尽量在同一未压缩会话里完成。
  • 每个 issue 实现 开新会话，只带 PRD + 该 issue。
  • /handoff = 新会话 + 文件；/compact（内置）= 同会话摘要，别在中途 compact。
