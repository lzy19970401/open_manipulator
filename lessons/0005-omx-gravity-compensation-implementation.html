2. 启动时发生了什么

真机 GC launch 做三件事：

  1. xacro 生成 robot_description，参数 ros2_control_type:=open_manipulator_x_current
  2. yaml 加载 open_manipulator_x_gc/hardware_controller_manager.yaml（4 关节、effort 命令、摩擦=0）
  3. spawner 激活 gravity_compensation_controller + joint_state_broadcaster

3. 模块分工（谁负责什么）

模块 职责 关节角？ 算力矩？
DynamixelHardware / GazeboSim 读编码器 → state；收 effort → Goal Current / 仿真力矩 源头（Present Position） 否
gravity_compensation_controller 读 state → KDL → 写 effort 读 interface 唯一计算者
joint_state_broadcaster 汇总 state → /joint_states 转发（观测） 否
robot_state_publisher URDF + joint_states → TF 否 否
GC 控制器不订阅 /joint_states 来做控制（那是给 OMY 主从 follower 用的）。 它读的是 ros2_control 的 hardware state interface。

4. ros2_control 接口（Issue 01）

Arm 四关节在 xacro 中声明：

<joint name="joint1">
  <command_interface name="effort"/>
  <state_interface name="position"/>
  <state_interface name="velocity"/>
</joint>
<!-- joint2–4 同上；gripper 仍为 position -->

真机 Dynamixel 映射：

state position  ←  Present Position（rad）
state velocity  ←  Present Velocity（rad/s）
command effort  →  Goal Current（电流模式，Operating Mode 0）

GC yaml 指定控制器只管 4 个 Arm 关节：

joints: [joint1, joint2, joint3, joint4]
command_interfaces: [effort]
state_interfaces: [position, velocity]
input_velocity_scaling_factors: [0, 0, 0, 0]      # Phase 1 纯 g(q)
input_acceleration_scaling_factors: [0, 0, 0, 0]

5. gravity_compensation_controller.cpp 生命周期

控制器是 ros2_control 插件，由 controller_manager 驱动：

on_init → on_configure → on_activate → [update × N @ 200Hz] → on_deactivate

5.1 on_configure — 建模型

  • 读 yaml：joints、摩擦系数、torque_scaling_factors
  • 从 robot_description 解析 URDF → KDL Tree（质量/惯性/关节轴决定 g(q)）
  • Tree 含夹爪共 6 关节；GC 只填 q_nr 0–3（joint1–4）

5.2 on_activate — 绑定 hardware 接口

  • joint_state_interface_[0] → position（4 个）
  • joint_state_interface_[1] → velocity（4 个）
  • joint_command_interface_[0] → effort（4 个）
  • 初始化 previous_velocities_，避免首帧 NaN

5.3 update() — 每帧核心（6 步）

1读关节角与角速度

assign_point_from_interface(joint_positions_, joint_state_interface_[0]);
assign_point_from_interface(joint_velocities_, joint_state_interface_[1]);

单位：rad、rad/s。来源是上一帧 hardware read() 写入的 state。

2速度/加速度预处理

OMX GC yaml 中 scaling 全为 0 → 等价 q̇ = 0、q̈ = 0，走纯重力（尽管实现用的是 RNEA 而非 JntToGravity）。

3填入 KDL 关节数组

for (i = 0..3) {
  q(i)     = joint_positions_[i];
  q_dot(i) = joint_velocities_[i];
  q_ddot(i)= joint_accelerations[i];
}

4KDL 逆动力学 → 补偿力矩（本课核心）

KDL::TreeIdSolver_RNE idsolver(tree_, KDL::Vector(0, 0, -9.81));
idsolver.CartToJnt(q, q_dot, q_ddot, f_ext_, torques);

输出 torques(i) 单位 N·m。在 q̇=q̈=0 时 ≈ g(q)。

home 位姿（q=0）数量级示例：joint2 ≈ −0.44 N·m，joint3 ≈ −0.36 N·m，joint4 ≈ −0.06 N·m（依赖 URDF 惯性）。

6写 effort 命令

effort = torques(i) * torque_scaling_factors[i];
joint_command_interface_[0][i].set_value(effort);

下一帧 hardware write() 把 effort 转为 Dynamixel Goal Current 或 Gazebo 关节力矩。

5.4 on_deactivate — 退出清零

四轮 effort 置 0；Issue 03 的 gc_shutdown_torque_disable 再对 ID 11–14 做 Torque Enable=0。

6. 一帧数据流（背诵版）

[Dynamixel 编码器]
       ↓ hardware read()
[ros2_control state: joint*/position, velocity]   ← 关节角
       ↓ update() Step 1
[joint_positions_, joint_velocities_]
       ↓ Step 3
[KDL q, q_dot, q_ddot]
       ↓ Step 4  CartToJnt
[torques(0..3)  单位 N·m]                           ← 补偿力矩
       ↓ Step 6
[command effort]
       ↓ hardware write()
[Goal Current → 电机电流 → 输出轴力矩]

Standard launch GC launch（真机） GC Gazebo launch

8. 实机单位陷阱（上机前必读）

控制器输出 N·m，但 dynamixel_hardware_interface 把 effort 映射为 Goal Current 时， model 里单位是 raw（倍率 1.0）——即未自动做 N·m → 电流换算。

Goal Current 寄存器（1 LSB ≈ 2.69 mA，X 系列）
物理力矩 τ_shaft ≈ Kt × I(A)

例：joint2 需 ≈ 0.44 N·m，XM430-W350-R Kt=1.783 N·m/A
  → multiplier = 1.783 × 0.00269 ≈ 0.004796
  → Goal Current_raw ≈ 0.44 / 0.004796 ≈ 92
  若直接写 0.44 → raw=0 → 几乎无补偿

Phase 1 实机验证前需：符号校准（见第 3 课）+ N·m→Goal Current 换算（后续 issue 或 torque_scaling_factors 临时 workaround）。
