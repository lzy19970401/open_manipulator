1. 问题设定：4 关节控 3 维位置

OpenMANIPULATOR-X 臂有 4 个转动关节，Phase 1 只控制末端执行器（EE）的位置 x ∈ ℝ³，不控制姿态。因此：

任务维数 m = 3  ·  关节维数 n = 4  →  冗余度 = n − m = 1

冗余意味着：同一个末端位置 x 通常对应无穷多组关节角 q。若只施加笛卡尔弹簧而不约束零空间，拖动示教时肘部构型可能漂移。Phase 1 用 Null-space posture preference 把关节拉回激活时捕获的 qcapture。

关节空间动力学（与第 11 课相同）：

M(q) q̈ + C(q, q̇) q̇ + g(q) = τ

控制律最终输出 τ，经 ros2_control effort 接口下发四关节。

2. 运动学：x、Jp 与 link1 系

2.1 正运动学

记 link1 为基座坐标系（参数 base_frame: link1），EE 帧为 end_effector_link。Pinocchio 给出世界系下各帧位姿 oMf，则 EE 在 link1 系下的位置为：

x(q) = 1RoT · ( opee − oplink1 )   或等价地   x = link1Tee 的平移部分

代码（task_impedance_control_law.cpp L18–27）：

pinocchio::forwardKinematics(model, data, q);
pinocchio::updateFramePlacements(model, data);
return data.oMf[base_frame_id].actInv(data.oMf[ee_frame_id]).translation();

函数名：compute_ee_position_in_base_frame。

2.2 位置雅可比

对 q 求导（速度层面）：

ẋ = Jp(q) q̇   ∈ ℝ³ˣⁿᵛ

实现步骤：

  1. Pinocchio 取 EE 的 6×nv 雅可比 J6（LOCAL_WORLD_ALIGNED，即线速度在世界系、随 EE 取向）。
  2. 取前 3 行得线速度部分，再左乘 link1Rworld = RbaseT，把线速度表达到 link1 系。
// task_impedance_control_law.cpp L42–47
pinocchio::getFrameJacobian(..., LOCAL_WORLD_ALIGNED, J6);
J_p = R_base_world.transpose() * J6.topRows<3>();

函数名：compute_position_jacobian_in_base_frame。末端线速度：ẋ = J_p * v（L186）。

2.3 雅可比时间导数 J̇p

对 ẋ = Jp q̇ 两边对时间求导（q 与 q̇ 都是 t 的函数）：

ẍ = J̇p(q, q̇) q̇ + Jp(q) q̈

Pinocchio：getFrameJacobianTimeVariation 给出 ∂J/∂t · q̇ 对应的 6 维项，同样投影到 link1 前三行 → dJ_p。

// L64–69
pinocchio::getFrameJacobianTimeVariation(..., dJ6);
dJ_p = R_base_world.transpose() * dJ6.topRows<3>();

3. 笛卡尔虚拟弹簧–阻尼：F

在 link1 系对 EE 位置误差施加对角刚度 Kp ∈ ℝ³ 与阻尼 Dp ∈ ℝ³（逐元素，单位 N/m、N·s/m）：

F = Kp ⊙ (xd,active − x) + Dp ⊙ (ẋd,active − ẋ)

⊙ 表示逐元素乘；代码用 Eigen 的 cwiseProduct：

// task_impedance_control_law.hpp — compute_cartesian_spring_force (inline)
return K_p.cwiseProduct(x_d - x) + D_p.cwiseProduct(x_d_dot - x_dot);

默认 yaml：stiffness: [200, 200, 200]，damping: [20, 20, 20]。平衡点附近约 2 N / cm 刚度量级。

物理含义：F 是施加在 EE 上的笛卡尔力（非力矩），把 EE「拉向」xd。这与关节空间弹簧 KjΔq 不同——后者直接加在广义坐标上。

4. 虚功原理：τtask = JpT F

设 EE 受到笛卡尔力 F（link1 系），产生虚位移 δx = Jp δq。虚功 δW = FT δx = FT Jp δq 应等于关节虚功 τT δq，对任意 δq 成立，故：

τtask = JpT F  ∈ ℝⁿᵛ

只有 Arm 四关节对应的分量非零并写入 effort；Gripper 不参与阻抗。

// task_impedance_control_law.cpp L221–222（完整版）
const Eigen::VectorXd tau_full = data.tau + J_p.transpose() * result.cartesian_force;

此处 data.tau 来自 rnea 前馈（下一节），J_p.transpose() * F 是笛卡尔反馈项。

5. 任务加速度与 ades 推导

5.1 期望任务加速度

若希望 EE 线加速度跟踪参考 ẍd,active，由 ẍ = J̇p q̇ + Jp q̈ 解出使 Jp q̈ 匹配的任务空间期望加速度：

Jp q̈ = ẍd,active − J̇p q̇   ⇒   ades ≜ ẍd,active − J̇p q̇

直觉：参考轨迹 ẍd 是 EE 应具有的加速度；J̇p q̇ 是「仅因 q、q̇ 变化导致 Jp 变化」带来的 EE 加速度项，需从前馈 q̈ 目标中扣除，否则 computed torque 会多补偿。

// L192–195
compute_position_jacobian_time_variation_in_base_frame(..., dJ_p);
const Eigen::Vector3d a_des = x_d_ddot_active - dJ_p * v;

5.2 与关节阻抗 computed torque 的平行

关节阻抗（第 11 课）令 q̈d 来自参考关节轨迹插值，直接 rnea(q,v,q̈_d)。

任务阻抗：q̈d 不直接给定，而是由任务加速度 ades 与零空间目标经 QP 反解，再 rnea(q,v,q̈_d)。

6. 零空间姿态偏好 q̈null

激活时记录 Posture capture qcapture（四关节角，on_activate L441–445）。希望冗余 DOF 上关节角不要远离该构型，用逐关节 PD 形式的期望关节加速度（仅 Arm 索引非零）：

q̈null,i = Knull,i · (qcapture,i − qi)   （i = 1…4）

注意：这是加速度级目标，不是力矩级弹簧；Knull 默认 [0.5, 0.5, 0.5, 0.5] N·m/rad 量级，应小于等效笛卡尔刚度，避免与主任务打架。

// compute_null_space_desired_acceleration — L72–86
qdd_null[arm_velocity_indices[i]] = null_space_stiffness[i] * (q_capture[i] - q[arm_configuration_indices[i]]);

7. QP 求 q̈d：从代价函数到 H、g

7.1 优化问题（PRD / ADR-0003）

minq̈   ‖Wtask (Jp q̈ − ades)‖² + ‖Wnull (q̈ − q̈null)‖²
s.t.   q̈min ≤ q̈ ≤ q̈max  （仅 Arm 四关节，逐元素盒约束）

Wtask = wtask I3，Wnull = wnull Inv（标量权重，yaml qp_task_weight、qp_null_weight）。

7.2 展开为 standard QP

记 etask = Jp q̈ − ades，enull = q̈ − q̈null。代价

J(q̈) = etaskT Wtask etask + enullT Wnull enull

展开第一项：

etaskT W etask = q̈T JT W J q̈ − 2 adesT W J q̈ + const

展开第二项：

enullT Wn enull = q̈T Wn q̈ − 2 q̈nullT Wn q̈ + const

ProxQP 标准形为 min ½ q̈T H q̈ + gT q̈，令梯度为零得：

H = 2 (JpT Wtask Jp + Wnull)
g = −2 (JpT Wtask ades + Wnull q̈null)

与 task_impedance_qp_solver.cpp L68–71 完全一致：

impl_->H.noalias() = 2.0 * (input.J_p.transpose() * W_task * input.J_p + W_null);
impl_->g.noalias() = -2.0 * (input.J_p.transpose() * W_task * input.a_des + W_null * input.qdd_null);

7.3 盒约束

对 Arm 关节 i，±joint_acceleration_limits[i]；其余 nv 维度（如 mimic gripper）上下界为 0。

// fill_joint_acceleration_bounds — L98–101
qdd_min[idx] = -joint_acceleration_limits[i];
qdd_max[idx] =  joint_acceleration_limits[i];

7.4 求解器

ProxQP（proxsuite）dense QP，100 Hz warm-start（WARM_START_WITH_PREVIOUS_RESULT）。失败时 qp_success=false，控制器输出零力矩（pinocchio_task_impedance_controller.cpp L219–226）。

7.5 冗余度与零空间

4 关节、3 维任务：Jp 行满秩时零空间维数为 1。QP 在「尽量满足 Jp q̈ ≈ ades」的同时，用第二项把 q̈ 拉向 q̈null；权重 wnull ≪ wtask 时主任务优先。

8. Computed torque：rnea + 反馈 + 摩擦

8.1 完整力矩合成

τ = M(q) q̈d + C(q,q̇)q̇ + g(q) + JpT F + τf

其中 q̈d 为 QP 解，M q̈d+C q̇+g 由 Pinocchio 一次 rnea 完成：

// L214–222
pinocchio::rnea(model, data, q, v, result.desired_joint_acceleration);
const Eigen::VectorXd tau_full = data.tau + J_p.transpose() * result.cartesian_force;

8.2 摩擦与硬件映射

与关节阻抗相同（om_impedance_utilities）：

τf,i = Fvi q̇i + Fci signε(q̇i)  （可选）
τcmd,i = si · αi · (τfull,i + τf,i) 
// L224–235
compute_friction_torque(...);
apply_effort_sign_and_scaling(tau_phys, effort_sign_flips[i], torque_scaling_factors[i]);

8.3 v1 简化版（tracer，生产路径已不用）

compute_task_impedance_torques_v1：q̈d = 0，无 QP、无零空间、无 J̇p：

τ = rnea(q, v, 0) + JpT F = C(q,q̇)q̇ + g(q) + JpT F

仅 G+C 前馈 + 笛卡尔弹簧；完整版在 compute_task_impedance_torques，由 update() 调用。

13. Hold 特例（ẋd=0, ẍd=0）

capture 后静止 hold 时，ades = −J̇p q̇（补偿构型变化引起的 EE 加速度）；若 q̇≈0 则 ades≈0，QP 主要满足 q̈≈q̈null 与 Jp q̈≈0 的折中。笛卡尔反馈 F ≈ Kp(xd−x) 提供主恢复力。

14. 自测（检索练习）

  1. 写出从 F 到 τtask 的虚功推导关键一步。
  2. 为什么 ades 里要减 J̇p q̇ 而不是直接用 ẍd？
  3. QP 代价函数展开后 H 的表达式是什么？对应哪两行 C++？
  4. 4 DOF 臂为何需要 qcapture？
参考答案
  1. δW = FTδx = FTJpδq = τTδq ⇒ τ = JpTF。
  2. 因为 ẍ = J̇p q̇ + Jp q̈；要令 EE 加速度为 ẍd，需 Jp q̈ = ẍd − J̇p q̇。
  3. H = 2(JpTWtaskJp + Wnull)；task_impedance_qp_solver.cpp L68–69。
  4. m=3, n=4 冗余 1；不约束零空间时拖动只定 x 会导致肘部构型漂移。
